# AI-Native PDF Reader

**读论文、读讲义的时候，旁边坐着一个随时能问的人。** 选中一句、就地问一句，回答会注明它引用的页码。所有批注、对话和阅读进度都留在你自己的电脑上。

[English](README.md) | 简体中文

## 为什么做这个

读硬材料的慢，往往不是读得慢，而是不断被打断：一个符号没见过、一步推导跳过去了、一句话默认了你还不知道的前提。高亮解决不了这个问题，切到聊天窗口又会丢掉原来的思路。

这个阅读器把问题留在原地。框住看不懂的地方，问一句，答案就出现在旁边——默认很短，需要时再展开。

## 你可以做什么

**就问选中的那一块。** 选中文字，或者在页面上拖一个区域。回答以这一页为依据，并标出用的是哪一段来源，方便你核对，而不是只能相信。

**答案出现在问题旁边。** 解释显示在原文边上的小框里，不会把原文顶走；你可以一边看着解释一边继续读，满意了再确认进对话，不满意就关掉。

**保留你自己的表达口味。** 可以导入自己的讲解风格——你确实觉得清楚的那种措辞——然后在某一轮里选用。它只影响语气，不会改变事实、数学条件或引用。

**照平时的习惯做批注。** 高亮、自由笔画、文字框，都是标准 PDF 批注，写进文件本身，普通 PDF 阅读器里照样能看。

**下次回来接着读。** 多标签、缩略图、搜索、缩放，阅读位置会恢复。对话和文档放在一起，上周问过的问题还在。

## 一次典型的使用

1. 打开一份 PDF，后台自动建立索引。
2. 框住一步看不懂的推导，问"这一步为什么成立"。
3. 先看简短解释，需要时再让它展开，满意后确认。
4. 把终于看懂的那段高亮，用自己的话补一条批注。
5. 关掉。下次打开，页码、高亮和对话都还在原处。

## 安装（Windows 10/11，64 位）

1. 下载 `AI-Native PDF Reader_1.0.3_x64-setup.exe`，核对发布页给出的 SHA-256。
2. 运行安装。安装包未签名，Windows 可能提示"未知发布者"，请先确认哈希。
3. 启动并打开一份 PDF。

需要 WebView2：Windows 11 已内置；Windows 10 若缺失请先安装微软官方运行时。安装包不捆绑运行时。

## 接入你自己的模型

软件本身不带密钥，也不会在后台自动调用模型。

1. 打开 **设置 → 模型**。
2. 选择 DeepSeek、OpenRouter，或任何兼容 OpenAI 的 Endpoint，并填写模型名。
3. 填入你自己的 API Key。密钥只写入本机凭据存储，不进入前端、日志或导出文件。
4. 用 **测试连接** 验证。没有 Key 也能阅读和批注，还可以用 Mock 模型先熟悉界面。

## 你的数据

- 设置：`%APPDATA%\io.github.ainativepdfreader\`
- 文档、索引、对话、备份：`%LOCALAPPDATA%\io.github.ainativepdfreader\data-manager\`

上面这些都在本机。你提问时，被选中的段落和你指定的页面会发给你配置的 Endpoint，除此之外不会发送别的内容。

## 需要如实说明的限制

- 仅支持 Windows；安装包未签名。
- 接近 16 MB 的 PDF 会在保存时被拒绝，原件和你的草稿都会保留。
- 批注在其他阅读器里能正常显示，但不宣称在 Edge、Adobe 里能完整往返编辑。
- 没有文字层的扫描页按图片处理，无法检索文字。
- AI 回答可能出错。软件会标出来源，方便核对；请把它当学习辅助，而不是权威结论。

## 从源码构建

需要 Node.js 20+、Rust 1.98+（MSVC 工具链）和 WebView2。

```powershell
npm ci                  # 安装依赖
npm run prepare:assets  # 复制 PDF.js/MuPDF 资源，获取固定字体并校验 SHA-256
npm run build           # 前端产物
npm run desktop:build   # 桌面程序
```

`npm run prepare:assets` 只下载一次固定的 Noto Sans SC 字体，并按
`worker/freetext-font.json` 校验大小和 SHA-256，不一致会拒绝使用；许可文本随仓库分发。

部分测试需要未随源码提供的素材（样例 PDF 与本地 worker 运行时），构建本身不需要。
