# AI-Native PDF Reader

[English](README.md) | 简体中文

读 PDF 时，遇到一个看不懂的地方，你会怎么做？打开 AI 聊天界面，截一张图，或者上传整份 PDF，再等它回复？来回切换实在麻烦。如果能直接在 PDF 阅读界面里向 AI 提问呢？

AI-Native PDF Reader 就是为此做的：选中文字、公式或图表，直接提问，把解释放在原文旁边。平时照常高亮、写字和记笔记。

当前版本为 **1.0.3 Public Beta**。不配置模型也能阅读、批注和保存 PDF；使用在线 AI 功能需要自己的 API Key。

## 功能

- 多标签阅读，支持缩略图、目录、搜索、缩放和阅读位置恢复。
- 高亮、自由笔画和文字框批注，按 `Ctrl+S` 保存到 PDF 文件中。
- 选中文字、框选区域或选择多页后提问，也可从当前 PDF 中检索相关内容。
- 在原文旁显示临时解释。确认后成为文字批注，再按 `Ctrl+S` 写入 PDF；也可以重新生成或取消。
- 在侧栏连续追问，对话历史保存在本机，重新打开文档后可继续查看。
- 新建、导入和切换讲解风格，自定义常用操作的应用内快捷键。

## 下载与安装

支持 Windows 10/11，64 位。

1. 从发布页下载 `AI-Native PDF Reader_1.0.3_x64-setup.exe`，核对随包提供的 SHA-256。
2. 运行安装包。由于尚未签名，Windows 可能提示“未知发布者”。
3. 安装后打开软件，选择一份 PDF 即可开始阅读。

软件需要 WebView2 运行时，安装包不包含它。如果系统缺少 WebView2，请先安装微软官方运行时。

## 配置 AI

在 **设置 → 模型** 中选择 DeepSeek、OpenRouter 或自定义兼容接口，填写模型名和自己的 API Key，然后点击 **保存配置**。自定义接口目前支持公网 HTTPS Chat Completions 接口。

API Key 保存在 Windows 系统凭据存储中。不想连接在线服务时，可以选择 Mock 模型试用交互流程。

**测试连接** 用于检查模型目录连接，实际回答效果仍需通过提问确认。

### 主模型和辅助模型怎么用

在模型设置的“模型角色”中，可以分别配置主模型和辅助模型。辅助模型可按需启用。

- **主模型**：建议选能力较强的模型，用来深入分析、梳理推导，或在侧栏连续追问。
- **辅助模型**：可以选成本更低的模型，处理术语、符号含义等简短问题，或生成临时解释。

配置后，在侧栏输入框或原位提问窗口的“本轮模型”中选择即可。两个地方会分别记住你的选择；原位解释框只显示回答时，点编辑按钮即可打开提问窗口切换模型。

我个人推荐：临时解释可以使用更便宜、甚至提供免费额度的辅助模型 API，把主模型留给需要深入分析的问题。涉及截图或图表时，请选择支持图像的模型，并在模型设置中勾选“支持图像”。

## 数据存储

默认位置：

- 设置：`%APPDATA%\io.github.ainativepdfreader\`
- 索引、对话、恢复稿和备份等应用数据：`%LOCALAPPDATA%\io.github.ainativepdfreader\data-manager\`

已保存的批注在 PDF 文件内，对话历史单独保存在本机。

发送 AI 问题时，软件会把问题和本轮上下文交给你配置的模型服务。上下文可能包括选中的文字或图像、手选及检索到的页面、相关历史对话和讲解风格指令。在侧栏提问时，可以在“本轮上下文选项”中检查、移除来源；同目录其他 PDF 的检索需要单独授权。

## 已知限制

- 目前只提供 Windows 版本，安装包尚未签名。
- 保存有大小和文件结构限制，接近 16 MB 的 PDF 可能被拒绝。遇到限制时会保留原件和恢复稿。
- 批注按标准 PDF 批注保存，但 Edge、Adobe 中的显示和再次编辑兼容性仍需继续验证。
- 没有文字层的扫描页按图片处理，无法进行文字检索。
- AI 解释可能出错，引用来源也需要核对，尤其是公式、推导和省略条件的地方。

## 从源码构建

需要 Node.js 24.19.0+ 和 npm 11+。构建 Windows 桌面程序还需要 Rust 1.98+、MSVC 工具链和 WebView2。

```powershell
npm ci
npm run build           # 构建前端
npm run desktop:build   # 构建桌面程序，不生成安装包
```

构建会准备 PDF.js、MuPDF.js 资源，并在本地缺少字体时下载固定版本的 Noto Sans SC，按 `worker/freetext-font.json` 校验大小和 SHA-256。字体许可随源码提供。

默认桌面构建使用 Mock，未启用在线模型。构建脚本 `scripts/desktop.mjs` 目前保留了开发机的 Rust 路径和工具链版本，换一台机器构建前需要调整。部分测试还依赖未随源码提供的样例 PDF 和本地 worker 运行时。
